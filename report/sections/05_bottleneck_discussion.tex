\section{Bottleneck Discussion}
\label{sec:bottleneck}

were responsible the largest portion of program time. Below is the configuration for the model and training set size used in the profiling. The batch size
parameter is only applicable to the second profiling result, after optimizations were introduced.

What we noticed in the above table were two things:
\begin{enumerate}
    \item Over $80\%$ of execution time was spent in the \texttt{linear\_kernel}.
    \item Individual kernel calls were reasonably fast, but the high number of invocations led to significant overhead.
\end{enumerate}
From these investigations, we determined the right course of action was to pursue optimizations similar to how modern day
LLM trainings operate. The first optimziation we went to implement was an optimization to reduce the time cost of the linear layer,
which is simply matrix multiplication. Utilizing the tiling method we learned about in lecture, we were able to reduce the 
time cost of the \texttt{linear\_kernel} by roughly $81.87$x in the average case. The next optimization we wanted to aim for
was one that many modern training systems do today, which is batching. By processing single tokens or single sequences at a time, we lose the benefit
of the massive amounts of parallelization available to us via the GPUs, and as such implementing the method to 
perform multiple sequences, at once, in a single batch was a reasonable next step.
